**A. `services.accorder_magasin` — un paramètre nommé, défaut `True`.**

    def accorder_magasin(cible, magasin_code: str, *, par, reappliquer: bool = True) -> Resultat:

Le défaut `True` n'est pas de la commodité : il préserve chaque appelant existant et chaque
test nommé existant, et il inscrit dans la signature elle-même **que la règle d'aujourd'hui
reste la règle**. Le CONTEXT l'exige : demander est *plus* sûr que la règle implicite, ce
n'est pas une raison de jeter la règle.

La boucle d'extension devient conditionnelle, **sans déplacer la garde T-03-62** :

    etendus: list[str] = []
    if avant and reappliquer:
        for code in sorted(set(Permission.values)):
            if ligne_de(cible, code, avant).etat != ETAT_ACTIF:
                continue
            ...

Écrire `if avant and reappliquer:` — pas un `return` anticipé, pas une seconde fonction.
Le reste de `accorder_magasin` (les refus, la création de l'`AccesMagasin`, la
journalisation de l'accès, le calcul d'`apres`) est **identique dans les deux cas**, parce
que l'accès au magasin est accordé quoi qu'il arrive : c'est le droit qui varie.

Étendre la docstring. Elle dit aujourd'hui que la règle est celle de 7.5 et nomme T-03-62 ;
y ajouter que la règle est désormais **proposée** plutôt que subie, que le propriétaire
peut demander un magasin vierge, et que **ni l'un ni l'autre choix n'étend une ligne
personnalisée** — `reappliquer` décide du sort des lignes *uniformes*, et de rien d'autre.
Sans cette phrase, un lecteur pressé lira « réappliquer les droits existants » comme
« tous les droits existants », ce qui est exactement l'élévation que la garde interdit.

**B. `BasculeMagasinSerializer` — un booléen facultatif, avec un `help_text`.**

    reappliquer = serializers.BooleanField(
        required=False,
        default=True,
        help_text=(
            "À l'ajout d'un magasin : étendre au nouveau magasin les droits accordés "
            "uniformément dans tous les autres. Les droits réglés magasin par magasin ne "
            "s'étendent jamais, quelle que soit la valeur. Sans effet au retrait."
        ),
    )

Le `help_text` part dans le schéma OpenAPI, donc dans la documentation que lit quiconque
appelle cette route, mobile de phase 11 compris. La seconde phrase y est ce qu'elle est
dans la docstring : la protection contre la mauvaise lecture du nom du champ.

**C. La vue — elle passe, elle ne décide pas.**

    operation = services.accorder_magasin if donnees["accorde"] else services.retirer_magasin
    ...

`retirer_magasin` n'accepte pas `reappliquer`, donc le passage doit être conditionnel.
Préférer l'explicite à une astuce de `kwargs` :

    with _erreurs_de_service():
        if donnees["accorde"]:
            resultat = services.accorder_magasin(
                cible, donnees["magasin_code"], par=request.user,
                reappliquer=donnees["reappliquer"],
            )
        else:
            resultat = services.retirer_magasin(
                cible, donnees["magasin_code"], par=request.user,
            )

Un `**{"reappliquer": ...} if accorde else {}` passerait le test et rendrait illisible
laquelle des deux opérations reçoit quoi. La table `operation = ... if ... else ...`
disparaît avec la branche.

Compléter la docstring de l'action `magasins` : elle annonce déjà les deux effets ; y
ajouter que l'extension est désormais un **choix du propriétaire**, énoncé par l'écran
avant d'être appliqué, et par défaut celui de 7.5.

L'`@extend_schema` de l'action ne change pas — `request=BasculeMagasinSerializer` suffit,
le champ est découvert par le sérialiseur.
