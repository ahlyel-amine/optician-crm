<objective>
Creer `web/` : Vite, React, TypeScript, vitest, Tailwind et shadcn/ui, avec le proxy
meme-origine et les premiers tests frontend nommes, rouges.

Purpose: `web/` n'existe pas. Aucun plan frontend ne peut demarrer sans lui, et la
decision la plus lourde de tout le shell est prise ici : **meme origine des le premier
jour**. Le serveur de developpement proxifie `/api`, donc le navigateur ne voit qu'une
origine, donc pas de CORS, pas de `django-cors-headers`, pas de prevol, et le cookie de
session et le jeton CSRF se comportent exactement comme en production. Chaque panne
classique du type "le cookie marche en local et pas en prod" est concue hors d'existence.

Second choix pris ici et non en phase 4 : **shadcn/ui**. `03-UI-SPEC.md` 0.5 renverse la
recherche sur ce point, et la raison tient en deux faits : la phase 3 a besoin d'un dialog
a piege de focus, d'un combobox, d'une palette de commandes, de switches, d'un collapsible
et d'un toast avec action d'annulation, tous des choses que la table "Don't Hand-Roll"
interdirait d'ecrire a la main ; et le modele de theme de shadcn **est** le mecanisme de
variables CSS dont la phase 9 a besoin pour BRAND-01. L'adopter en phase 4 signifierait
restyler le shell.

Output: un `web/` qui construit, un `npm --prefix web test` qui sort, et deux tests
frontend nommes qui echouent pour la bonne raison.
</objective>

| Boundary | Description |
|---|---|
| navigateur vers serveur de developpement Vite | le proxy fait de `/api` la meme origine ; c'est ce qui supprime CORS de l'equation |
| registre npm vers le depot | chaque paquet installe est du code tiers execute a la construction |
| registre shadcn vers le depot | les blocs sont **vendorises** dans `web/src/components/ui`, donc lisibles et versionnes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-03-11 | Spoofing | une origine distincte pour la SPA imposerait `SameSite=None` et `CORS_ALLOW_CREDENTIALS`, affaiblissant materiellement l'argument de session de toute la phase | mitigate | proxy meme-origine en developpement et SPA servie depuis la meme origine en production ; aucune dependance CORS n'est installee, et le critere d'acceptation le verifie |
| T-03-12 | Tampering | un registre de composants tiers non verifie injecte du code dans le bundle | mitigate | registre officiel shadcn uniquement, blocs vendorises et committes donc relisibles ; `03-UI-SPEC.md` section 12 interdit tout registre tiers dans cette phase sans passer la porte de vetting |
| T-03-13 | Tampering | une derive de version non epinglee change le comportement de la construction entre deux machines | mitigate | toutes les versions epinglees exactement, `package-lock.json` committe, `npm ci` en verification |
| T-03-14 | Denial of service | `npm test` en mode surveillance ne sort jamais et bloque l'execution de la phase | mitigate | `"test": "vitest run"`, et le critere d'acceptation exige un code de sortie |
