<objective>
Stand up the repository: a uv-managed Python 3.13 project with an exactly-pinned stack, a four-module
settings package, the Docker Compose topology that matches production (PostgreSQL 18 + PgBouncer in
transaction mode + Redis 8), and the permanent settings assertions that make TENANT-08 true.

This is the first half of Wave 0 from `02-VALIDATION.md`. Nothing exists in this repository yet
except `.planning/` and `CLAUDE.md`.

Purpose: TENANT-08 is not a feature, it is a set of configuration invariants. Four one-line settings
(`CONN_MAX_AGE = 0`, no `ATOMIC_REQUESTS`, `DISABLE_SERVER_SIDE_CURSORS = True`, PgBouncer
`min_pool_size = 0`) are the entire difference between "server connections scale with concurrency"
and "server connections scale with client count". Each gets a test so configuration drift turns the
suite red rather than paging someone at 300 clients.

Output: a repository where `uv run pytest` runs, `docker compose up -d` works, and the pooling
topology is asserted rather than assumed.
</objective>

<corrections>
Three things in this plan deliberately depart from what a Django developer would write by reflex.
They are not negotiable and the acceptance criteria check each one.

1. **The top-level package is `plateforme/`, never `platform/`.**
   `02-RESEARCH.md` proposes `platform/` for the quarantined infrastructure code. `platform` is a
   **Python standard-library module** (`platform.python_version()`, `platform.machine()`), imported
   by psycopg, gunicorn, Sentry and Django itself. A top-level `platform/` package sits on
   `sys.path[0]` and shadows it, producing `AttributeError: module 'platform' has no attribute
   'python_version'` from deep inside a third-party library. Use `plateforme/`, which also matches
   the French `domaine/` sibling. Every dotted path in `02-RESEARCH.md` that begins `platform.`
   becomes `plateforme.` — including `DATABASE_ROUTERS = ["plateforme.tenancy.router.TenantRouter"]`.

2. **`ATOMIC_REQUESTS` is never written, not even as `False`.**
   CLAUDE.md non-negotiable #12. `BaseHandler.make_view_atomic()` iterates *every* alias in
   `connections.settings`. Writing it at all invites a later "why is this False?" edit. The test
   asserts the effective value is falsy on every alias, which covers both spellings.

3. **The Compose host ports must avoid 8000.** Port 8000 on this machine is already bound by an
   unrelated container (`aida-gateway`). Verify each host port is free before writing it.
</corrections>

      For every alias in `settings.DATABASES`, `cfg.get("CONN_MAX_AGE")` is exactly `0`.
      Assertion message: `CONN_MAX_AGE > 0` makes each worker thread hold a *client* connection per
      alias it has ever touched, so client connections become `C_web x N_touched` and blow through
      `max_client_conn`. PgBouncer owns pooling.

    - `test_tenant08_no_alias_has_atomic_requests`
      For every alias, `bool(cfg.get("ATOMIC_REQUESTS", False))` is `False`. Assertion message cites

      For every alias, `cfg.get("DISABLE_SERVER_SIDE_CURSORS")` is `True`. Server-side cursors are
      local to a connection and survive the end of a transaction under autocommit, which is exactly
      what transaction-mode pooling recycles underneath you.

    All three iterate `settings.DATABASES` rather than naming aliases, so they automatically cover
    `tenant_a`, `tenant_b` and any alias a future phase adds.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app process -> PgBouncer -> PostgreSQL | Every business query crosses a *shared, recycled* server connection. Anything set at session scope leaks to the next user of that connection. |
| repository -> developer machine / CI | `.env` carries the PostgreSQL superuser password and the Fernet key. A committed `.env` is a full compromise of every client database. |
| Compose host ports -> local network | Postgres and PgBouncer published on the host are reachable by anything on the machine. |
