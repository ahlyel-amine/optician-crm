<objective>
Build the fail-closed tenancy layer: the context variable, the runtime connection registry, the
router that raises instead of falling back, the startup system check that catches unclassified apps,
the middleware that binds and clears, and the Celery task base that refuses a task with no client.

This is TENANT-04 and it is the security core of the entire product. `CLAUDE.md`: *"a leak across
clients is a security failure, not a bug."* Everything in Phases 3 through 12 sits on top of this.

Purpose: four defences, layered, so no single mistake is a breach.
  1. The router **raises** when no client is bound. Returning `None` falls through to `default`.
  2. The context is **cleared with `set(_UNSET)`, never `reset(token)`**, and entry asserts unset.
  3. `allow_migrate` keeps business tables **out of the control-plane database entirely**, so a
     `.using("default")` that bypasses the router hits `relation does not exist`. This is the only
     defence a router bypass cannot defeat.
  4. A system check fails at startup if any installed app is unclassified, so defence 3 cannot
     silently stop covering a new app in Phase 7.

Output: no code in this repository can read or write business data without knowing whose it is.
</objective>

<five_corrections>
The research corrected five things that would otherwise be written into this exact code. Three of
them live in this plan. They are verified findings, not opinions — implement the corrected version.

1. **`connections.ensure_defaults()` and `connections.prepare_test_settings()` do not exist.**
   Removed in Django **4.1** (Aug 2022), confirmed across nine tagged versions. Every blog post on
   runtime tenant registration still recommends them. Build the alias config from
   `copy.deepcopy(settings.DATABASES["default"])`, which has already been through
   `ConnectionHandler.configure_settings()` and therefore carries every key `DatabaseWrapper`
   requires. A `KeyError` naming a `DATABASES` key is the warning sign that someone reached for the
   old incantation.

2. **`ContextVar.reset(token)` restores the previous value — it does not clear.**
   `cv.set("LEAKED"); tok = cv.set("current"); cv.reset(tok)` leaves `cv.get() == "LEAKED"`.
   Reproduced locally. On a reused worker thread already carrying a leak, a `finally: reset(token)`
   faithfully re-installs the leak. `CLAUDE.md` non-negotiable #8 says "reset it in a finally" and
   has been **corrected**: `finally: _current.set(_UNSET)`, plus an assert-unset-on-entry guard so a
   leak is loud instead of silent.

3. **Evict an alias with `connections[alias].close()` then `del connections[alias]`.**
   **Never** `del connections.settings[alias]`. `close_old_connections` (wired to both
   `request_started` and `request_finished`) iterates `connections.all(initialized_only=True)`,
   which iterates `iter(self.settings)`. Removing the settings entry makes the still-open
   `DatabaseWrapper` invisible to that loop and orphans the socket permanently.
   `BaseConnectionHandler.__delitem__` does `delattr(self._connections, key)` — it drops only the
   thread-local wrapper, which is exactly the primitive wanted.

(The other two — never `ATOMIC_REQUESTS = True`, and static test aliases rather than a
`django_db_setup` override — were handled in plans 02-01 and 02-02.)
</five_corrections>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request -> application code | Untrusted input decides *whose database* is used. The tenant identity must come from an authenticated claim, never from anything the caller can set freely. |
| worker thread / prefork process -> next request or task | Threads and processes are reused. Anything left in a `ContextVar` outlives the request that set it. |
| application code -> `default` connection | `.using("default")` bypasses the router completely. The router is defence #1, not a guarantee. |
| error telemetry -> Sentry (third party, possibly outside the EU) | Event bodies could carry ordonnance values, which are law 09-08 sensitive data. |
