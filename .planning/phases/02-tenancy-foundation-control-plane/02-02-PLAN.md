<red_suite_convention>
Plan 02-01 declared a `pending` pytest marker and the quick-loop command
`uv run pytest -x -q -m "not slow and not pending"`.

This plan creates the six named test files from the Wave 0 checklist. Almost none of their
implementations exist yet. Two rules make that workable instead of a permanently red suite:

1. **Every not-yet-implementable test is decorated `@pytest.mark.pending`** with a docstring naming
   the plan that will remove the marker (e.g. `"pending: implemented by plan 02-03"`).
2. **Imports of not-yet-existing modules go inside the test function body, never at module scope.**
   A module-level `from plateforme.tenancy.router import TenantRouter` turns a missing module into a
   *collection error*, which `-m "not pending"` cannot deselect because deselection happens after
   import. A function-local import turns it into a clean per-test failure, which is what RED should
   look like.

The phase gate is `grep -rn "mark.pending" tests/` returning nothing.
</red_suite_convention>
